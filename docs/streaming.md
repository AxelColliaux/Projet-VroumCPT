# Spark Streaming Analysis — Documentation

`streaming/streaming_analysis.py` is a Spark Structured Streaming job that reads vehicle
state reports, computes error-rate metrics over tumbling time windows, and emits alerts
when those metrics exceed configured thresholds.

## How It Works

```
Input stream                 Windowed aggregation         Output stream
─────────────────    ─────────────────────────────    ─────────────────────
vehicle-states    ──▶  global error rate         ──▶  alerts (if > threshold)
(Kafka / socket)  ──▶  error rate per make       ──▶
                  ──▶  error rate per vehicle_id  ──▶
```

The job opens **three independent streaming queries** (one per metric) so each can be
checkpointed and restarted independently.

### Metrics

| Metric          | Computation                                      | Default threshold |
|-----------------|--------------------------------------------------|-------------------|
| Global          | `mean(has_error)` across all records in window   | 0.15              |
| Per make        | `mean(has_error)` grouped by `make`              | 0.25              |
| Per vehicle_id  | `mean(has_error)` grouped by `vehicle_id`        | 0.50              |

`has_error = 1` if `errors` list is non-empty, `0` otherwise.

Thresholds are loaded from `config/thresholds.json` (generated by the batch job).
If the file doesn't exist, hard-coded defaults are used.

### Alert Format

```json
{
  "alert_type": "global",
  "entity": "global",
  "metric_value": 0.32,
  "threshold": 0.15,
  "window_start": "2026-06-17 11:29:00",
  "window_end": "2026-06-17 11:29:30",
  "generated_at": "2026-06-17T11:29:31+00:00"
}
```

`alert_type` is `global`, `make`, or `vehicle`.  
`entity` is `"global"`, the make name, or the vehicle ID.

## Running the Job

### Socket mode (minimal, no Kafka)

Start a generator piped to netcat in one terminal:
```bash
python generator/generator.py --no-kafka --rate 5 | nc -lk 9999
```

Submit the Spark job in another terminal:
```bash
spark-submit streaming/streaming_analysis.py \
    --source socket \
    --sink file \
    --output-dir output/alerts
```

### Kafka mode (full)

```bash
spark-submit \
  --packages org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.0 \
  streaming/streaming_analysis.py \
    --source kafka \
    --kafka-broker localhost:9092 \
    --sink kafka \
    --thresholds config/thresholds.json
```

### Console mode (debugging)

```bash
spark-submit \
  --packages org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.0 \
  streaming/streaming_analysis.py \
    --source kafka \
    --sink console
```

## CLI Reference

| Option                    | Default           | Description                                          |
|---------------------------|-------------------|------------------------------------------------------|
| `--source`                | `socket`          | `socket` or `kafka`                                  |
| `--socket-host`           | `localhost`       | Host for socket source                               |
| `--socket-port`           | `9999`            | Port for socket source                               |
| `--kafka-broker`          | `kafka:9092`      | Kafka bootstrap server                               |
| `--input-topic`           | `vehicle-states`  | Kafka input topic                                    |
| `--output-topic`          | `alerts`          | Kafka output topic (kafka sink)                      |
| `--group-id`              | `spark-streaming` | Kafka consumer group (must match ACL in secure mode) |
| `--sink`                  | `file`            | `file`, `kafka`, or `console`                        |
| `--output-dir`            | `output/alerts`   | Directory for JSON output (file sink)                |
| `--thresholds`            | (defaults used)   | Path to `thresholds.json`                            |
| `--window-duration`       | `30 seconds`      | Tumbling window size                                 |
| `--trigger-interval`      | `10 seconds`      | How often Spark processes a micro-batch              |
| `--watermark`             | `1 minute`        | Late data tolerance                                  |

### Security options (Kafka)

| Option                        | Description                                    |
|-------------------------------|------------------------------------------------|
| `--kafka-security-protocol`   | `PLAINTEXT` (default) / `SASL_SSL`            |
| `--kafka-sasl-mechanism`      | `SCRAM-SHA-256`                                |
| `--kafka-sasl-jaas-config`    | Full JAAS string (see security.md)             |
| `--ssl-truststore-location`   | Path to truststore JKS                         |
| `--ssl-truststore-password`   | Truststore password                            |

## Checkpointing

Each query writes checkpoint data to `/tmp/vroumcpt-checkpoints/<query-name>/`.
On restart, Spark resumes from where it left off (no duplicate processing).
In production, point checkpoints to HDFS or S3.

## Batch Threshold Calculator

See [threshold_calculator](#batch-threshold-calculator) and `batch/threshold_calculator.py`.

The batch job reads historical data, computes the 99th percentile of each metric's
distribution across all windows, and writes `config/thresholds.json`. Re-run it
periodically as the fleet grows.
